# 模块设计文档：磁盘缓存维护器（DiskCacheMaintainer）

> **所属层**：Layer 2 持续维护层  
> **模块ID**：MOD-DSK-001  
> **状态**：Planned  
> **学习协作建议**：当前只做 L0 需求与实验设计，不进入真实预读实现。学习者可分析 ETW/磁盘指标、设计 fake 和取消测试；AI 负责阻止需求在没有 workload 与 A/B 证据时膨胀。绿色区是只读观测，黄色不变量是有界、限速、可取消且不与加载争用；红色区是通用“缓存优化”、无白名单批量读盘或清空系统缓存。

## 结论

暂不实现通用“磁盘缓存优化”。Windows Cache Manager/SysMain 已完成通用缓存管理，盲目预读可能争用磁盘带宽并挤出有效缓存。

## 允许的未来范围

只有在游戏配置提供明确、安全、只读的文件清单并且实验显示加载收益时，才实现：

- 有界、限速、可取消的顺序预读；
- 游戏进入加载或磁盘队列升高时立即取消；
- 每请求设最大字节数和总时限；
- 支持文件被更新、删除、共享占用等错误。

## 禁止事项

不安装 MiniFilter，不 Hook 文件 API，不扫描整个游戏目录，不修改系统缓存参数，不解析或绕过受保护游戏资源。

## 进入实现的门槛

必须先定义可复现 workload，并用加载耗时、磁盘队列、读字节、帧时间进行配对 A/B；无稳定收益则保持 Planned。
