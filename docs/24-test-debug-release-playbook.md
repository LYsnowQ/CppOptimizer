# 测试、调试与发布操作手册

> **目标**：让第一次进行 Windows 底层开发时，每一步都有可执行的验证和恢复流程。具体教学分工、L0～L4 梯度和绿/黄/红实验边界见 [00-project-ai-learning-harness.md](00-project-ai-learning-harness.md)。

---

## 1. 环境分级

| 环境 | 用途 | 允许风险 |
|---|---|---|
| Dev 主机标准用户 | 编译、单元测试、R0/R1 | 不允许 R2/R3 |
| Dev 主机提升控制台 | 权限错误路径、单次实验 | 谨慎 R2，R3 默认不允许 |
| Windows Sandbox/VM | Native API、崩溃和恢复测试 | R3 |
| 专用测试机 | GPU/游戏真实 A/B | 经审批 R3 |
| 日常游戏主机 | 发布候选验证 | 只用已通过门禁功能 |

虚拟机不适合评价真实 GPU 性能，但适合权限、异常和恢复路径。

---

## 2. 构建检查

每次提交至少：

1. x64 Debug 编译；
2. x64 Release 编译；
3. 新代码零编译警告；
4. 静态分析 `/analyze`（至少定期）；
5. 文档本地链接检查；
6. 项目 XML/CMake 配置检查；
7. 单元测试；
8. 启停 smoke test。

Win32 不作为发布门禁，避免未文档化结构在位宽差异下产生错误假设。MSVC 是正式支持工具链；MinGW 可用于辅助语法/可移植性检查，但其 CRT、SDK 头和链接行为不同，不能替代 MSVC 验证。

## 3. 调试工具分工

| 工具 | 用途 |
|---|---|
| Visual Studio Debugger | 用户态断点、线程、异常、内存 |
| WinDbg Preview | dump、复杂异常、未来内核调试 |
| Process Explorer | 句柄、线程、优先级、token |
| Process Monitor | 文件/注册表访问和权限失败 |
| RAMMap | 内存列表，仅观察，不把可用内存增加当收益 |
| WPA/WPR | CPU、调度、磁盘、能耗、唤醒分析 |
| GPUView | GPU 调度与竞争 |
| PresentMon/CapFrameX | 帧时间 |
| Application Verifier | 句柄、堆、锁等错误 |
| Driver Verifier | 未来驱动专用；当前项目不启用 |

## 4. 学习型调试闭环

每个由学习者参与实现的小任务，除编译和测试外，至少完成以下四项中的三项：

1. 在成功路径设置断点，观察关键参数和返回值；
2. 主动制造一个绿色范围内的失败，记录原始错误域和 code；
3. 检查资源在成功、失败和取消路径上的释放；
4. 完成一个安全变体，并证明没有突破黄色不变量。

AI 给出完整示范时，也必须给观察点和变体，不能以“复制后运行成功”作为教学完成。测试不能只验证结果值，还应验证未发生的行为，例如没有请求管理员权限、没有打开 Native 写、没有泄漏租约。

每次验证记录应区分：

- `Built`：实际使用何种编译器和配置构建；
- `Tested`：实际执行了哪些自动测试；
- `Observed`：使用何种工具做人工观察；
- `Not verified`：哪些项目未验证及原因。

## 5. 测试金字塔

### 单元测试

不调用真实系统副作用：配置校验、状态机、迟滞、冲突解决、租约引用计数、错误转换、消息解析。

### 组件测试

通过接口注入 fake platform backend，模拟：访问拒绝、目标退出、超时、设备丢失、PDH warming-up、Native API 不支持。

### 集成测试

真实调用 R0/R1 API：进程枚举、Power Request、测试子进程优先级、配置热重载、服务控制台模式。

### 系统/实验测试

R2/R3 在隔离环境执行，使用操作许可、审计和恢复验证。

## 6. 必测故障

- API 第一步成功、第二步失败时是否回滚；
- Stop 与 callback 同时发生；
- 目标进程在 OpenProcess 前后退出；
- PID 被重用；
- 配置保存产生连续文件通知；
- 日志磁盘满/目录只读；
- 系统睡眠和恢复；
- 用户注销、锁屏和 RDP；
- GPU device removed；
- 服务启动超时和 SCM stop；
- 上次进程在全局修改后被强制结束。

## 7. MemoryTuner 实验剧本

1. 仅运行 `status`，记录内存、硬缺页和磁盘指标；
2. 确认编译期开关和配置默认关闭；
3. 在 VM/测试机使用提升控制台；
4. 只执行一次 Light；
5. 记录 NTSTATUS、前后列表和耗时；
6. 继续观察 5～10 分钟硬缺页和读取量；
7. 运行实际加载 workload；
8. 若加载变慢或 I/O 增加，记录负结果并保持禁用；
9. 不自动测试 Aggressive。

---

## 8. 性能实验设计

- 固定游戏版本、驱动、电源、分辨率和场景；
- 预热后开始；
- A/B 顺序随机或 ABBA，避免温度/缓存偏差；
- 每组至少 10 次短重复或足够长的稳定采样；
- 同时报 P50/P95/P99、1% Low、CPU/GPU 功耗、温度和优化器开销；
- 保留原始 CSV/ETL 和脚本；
- 不挑选最好的一次。

---

## 9. 发布清单

- 版本号、CHANGELOG、许可证；
- x64 Release、PDB 和符号归档；
- 二进制签名（正式分发阶段）；
- 默认配置审查：R2/R3 全部关闭；
- 标准用户安装/运行路径；
- 卸载和状态恢复测试；
- Defender/VirusTotal 误报检查（不上传含秘密的私有构建）；
- 反作弊兼容声明只描述行为边界，不承诺所有厂商永不拦截；
- 已知问题和实验功能风险说明。

---

## 10. 崩溃收集

用户态可在正式阶段增加 Windows Error Reporting 或受控 minidump。dump 可能包含路径和内存数据，必须告知用户、限制 ACL，上传需显式同意。异常处理器中不执行复杂恢复；全局状态恢复由下一次启动的恢复流程负责。
