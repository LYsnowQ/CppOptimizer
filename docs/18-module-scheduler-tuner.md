# 模块设计文档：调度参数微调器（SchedulerTuner）

> **所属层**：Layer 2 持续维护层  
> **模块ID**：MOD-SCH-001  
> **状态**：Experimental  
> **学习协作建议**：默认 L0/L1。AI 主导调度语义、租约和真实修改门禁；学习者完成优化器自身线程的只读观测、fake、配置校验和恢复测试。绿色区是观测与纯策略，黄色不变量是只影响明确白名单、可逆和不猜测大小核；红色区是游戏绑核、实时优先级、关闭动态 boost 或未文档化全局调度修改。

## 职责

- 降低优化器自身后台线程的功耗和调度干扰；
- 可选将明确白名单的后台辅助进程置于 Background Mode；
- 在目标变前台或租约释放时恢复。

## 非目标

不调整游戏 CPU affinity，不绑核，不识别/猜测大小核，不设置实时优先级，不关闭动态优先级提升，不依赖未文档化 I/O 优先级 API。

## 技术路线

- 自身后台线程：`SetThreadInformation(ThreadPowerThrottling, ...)` 申请 EcoQoS；
- 经用户明确配置的后台进程：评估 `PROCESS_MODE_BACKGROUND_BEGIN/END`；
- 所有修改使用租约、generation 校验和条件恢复。

## 验收

WPA 验证优化器唤醒和功耗下降；确认游戏进程调度属性未变化；前后台切换、退出和权限不足均安全。
